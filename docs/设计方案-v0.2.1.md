## 一、目标与非目标

**目标（按优先级，P1 修订）**：

1. **立场连续性**（主卖点）：质询回应由写过 R1 的同一个存活子智能体
   产生，消除克隆体立场漂移。v0.2 原文以"省 token"为第一目标——审议
   裁定该收益未证明且方向未证（结构不等式 vs 增量计费之分歧无实测可
   裁），降级为 G5 出数后的第二目标。
2. token 节省（**待证假设**）：若 G5 实测续谈轮 input 显著低于冷启动
   对照，则按实测值修订标称；否则本目标作废。
3. 为纪律层补机器回读：归档审计器（events 对账 cost.calls）。

**非目标（明确不做）**：

- 不改变阁员隔离不变量（阁员之间仍不直接通信，父智能体仍是唯一集成
  点；续谈只发生在 主持人↔席位 这条边上）。
- 不动 R1 的并发派发形态、议定书 schema v2（仅增 `replayable` 披露
  字段）、角色包与钉扎表结构。
- 不引入 agent-team 实验包（v0.1 评估结论维持）。
- **（P5 新增）不做人格路径引用**——见 §四.2'。
- **（P6 新增）config 不承载续谈开关**——见 §五'。

## 二、核心变更：席位生命周期

### 2.1 现状（v0.1.1）

```
R1: spawn 席A(简报=人格+角色卡+议题+材料) → 立场书 → 席位死亡
R2: spawn 席A′(简报=人格+角色卡+席A立场书原文+对手原文+质询点) → 回应
```

立场连续性 = 内嵌原文；成本 = 每轮重付全量简报。

### 2.2 v0.2.1 目标态（P1 修订）

```
R1: spawn 席A(continuable, 简报同 v0.1) → 立场书 → 席位存活（保留 id）
停等: 席位随父智能体回合边界挂起（dsh continuable 语义，G1 实证）
R2: send_message(席A, 消息=对手材料原文+质询点+输出格式要求) → 回应
```

- **第一收益（本稿主卖点）**：立场连续性由会话承载，取代文本重建。
- **第二收益（探针场初证，n=1）**：2026-10-11 G5 探针场实测【核验：宿主
  session_projcache 直读】——计费口径 = **全量重放 + prompt caching**：
  续谈 R2 单步 input 17.9K 中 17.4K 走缓存读（跨父回合边界全额命中），
  全价 uncached 仅 249 vs 冷启动首步 ≈4000（比值≈0.06）；DeepSeek 系
  缓存折扣 r≤0.2 下等效成本省 3–5×（临界 r≈0.22）。**意外红利（金额更
  大）**：续谈席位不重复 R1 已做的工具核验，本场省 ~10K uncached——
  立场连续性的成本侧实证。残余不确定性：缓存 TTL 失活（停等超时后
  cacheRead 变 uncached 全价）、kimi/zai 路由的缓存策略未测。
- 不省的：对手 R1 原文（隔离不变量决定它只能经主持人传递，"全文优
  先、摘录兜底"规则不变）。
- 点名追问同理走 send_message，不再全新委派。

### 2.3 不变量改写（v0.1.1 原文 → v0.2.1）

> 旧：**不使用续谈**……停等边界之后一律全新委派。
> 新：**续谈优先、冷启动兜底**（默认关闭，实证翻转——见 §五'）。席位自
> spawn 起持续存活至合议；任何一次 send_message 失败/超时/目标席位已
> 终止，立即退回 v0.1 路径——全新委派 + 简报内嵌该席全部已有材料
> （人格+角色卡+R1 原文），计 reassigns。灾备表增一行：`席位会话丢失/
> 压缩失真 → 冷启动重派，disclosure 注明退化`。

### 2.4 升档×续谈交互（P9 新增，远·漏洞1 修补）

**升档即冷启动**：standard→advanced 重调 cabinet_start 后，旧场存活席位
一律不再引用（席位 id 仅运行期存在，新计划无法、也不得引用）——升档场
的 R2 全部按新计划全新委派。此条明文写入计划文本，消除"计划自包含从
纯文本变成文本+运行时态"的破口。

### 2.5 诚实规则增补

续谈后主持人看不到席位的完整内部推理历史（只见报告），议定书
disclosure 增固定一句："本场立场连续性由各席会话承载，主持人可见面
= 各席报告文本"。归档的 round-N.jsonl 仍是权威记录——若某席 R2 与其
R1 出现无解释的立场翻转，主持人须在 divergence 记"新发现"而非默认其
已被说服。

**（P9 新增）可重放性披露**：冷启动形态下每轮可由 round-N.jsonl 独立
重建；续谈形态下 R2 依赖宿主会话压缩态，归档是权威记录但**不再可重
放**。protocol.json 增 `replayable` 字段（true/false），续谈场次标
false——这是用可审计性换连续性（可能还有 token），必须在议定书里
承认这笔交易。

### 2.6 预算公式影响（P1/P2 修订）

- 调用轨口径不变（spawn 与 send_message 都计委派次数；cap 公式
  `seats*rounds + seats + 1` 不动）。**续谈不省调用轨一格**（审议确
  认：advanced 16 次上限里 R2 全席恰占 5 次，续谈与冷启动重派消耗相
  同）。
- token 轨：**标称值维持 v0.1 数值不动**，直至 G5 出数且 n≥3 场实测
  中位数支持修订；deviation 逐场记录。v0.2 原文"预估 19K→15–16K"作废
  （其推导链 34K×40–55% 证据等级不合格，见 §三'注）。**量测口径（探针场
  起升级）**：宿主存储实测（tokenUsage 三桶：uncachedInput / cacheRead /
  output），替代"简报出+报告入"的字符估算；R2 全文优先 ×1.8 措辞保留
  作历史预期、以实测为准。

## 四、同批进入 v0.2.1 的次席变更

1. **归档审计器**（约 20 行脚本）：读 `.cabinet/*/events.jsonl` 重建实际
   委派次数（含 send_message 续谈派发——见第 3 条事件类），对账
   protocol.cost.calls；对不上即报。**token 真源（探针场 V5）**：宿主
   `storages/session_projcache/sessions/<agentId>.json` 的 tokenUsage 三桶，
   可逐席位直读，cost.tokens 由"估算"升级为"实测代抄"。每场归档后必跑，
   结果写入 index.jsonl 新列 `audit`。
2. **events.jsonl 收窄为最小集 + 续谈派发事件类（P9）**：seq/t/phase/
   actor/event 五字段 + 派发（**spawn 与 send_message 分列事件类**）/
   送达/预算三类必记事件。v0.2 原文"§2.5 规定 send_message 计委派"与
   最小集只有"派发/送达"的口径矛盾就此消除——否则审计器重建数与
   cost.calls 必然对不上。
3. **ROI 计数**：index.jsonl 每场增 `calls` 与 `gate_blocks` 两列。
4. **故障注入测试**：verify.mjs 增一组 smoke——构造钉扎全不可用、空
   sessionModel 两类静默故障场景，断言计划文本仍含响亮中止路径。

### 四.2'（P5：v0.2 §四.2 人格路径引用——整项移出）

**不做。** 双理由合流：工程账（人格全文 8×1.1–1.4KB ≈ 9KB，计划文本只
付父智能体一次，真正烧钱的是子智能体简报——哈希机检却是新增发布门
成本）+ 结构账（路径引用把内嵌常量变成运行时文件依赖，与"计划自包
含"不变量冲突；HMR 可在 cabinet_start 与 R2 之间换掉 ministers/ 文
件，发布门哈希挡不住运行期漂移）。

**重开条件**：G5 判"全量重付"时，计划文本随父智能体每轮重付，9KB 收
益需重估——届时若重开，哈希必须由 buildInstruction **内嵌进计划文本、
主持人读文件后运行期对拍**，而非发布门机检。

## 五、风险与回退（P6 修订）

| 风险 | 等级 | 缓解 |
|---|---|---|
| 续谈语义与文档不符（dsh rc 阶段行为漂移） | 高 | G1 硬门槛；版本闸 peer 已就位；计划引用工具须在宿主工具面存在（见 §六'.D4 机检） |
| **计费口径反向：续谈更贵**（审议新增） | 中（探针场初证缓解：缓存命中+折扣下反转；残余 = TTL 失活与非 DS 路由未测） | G5 等效成本口径门 + **TTL 双时点探针**（同一 ≤20 字探针在第 1 分钟与超 TTL 后各跑一次，分离"折扣率"与"缓存失活"两变量） |
| 席位长期存活导致上下文膨胀、质量反降 | 中 | G2 对抗探针；连续两场 deviation 恶化即回退冷启动 |
| 双形态（续谈/冷启动）并存增加规程复杂度 | 中 | 参数化分支单真源 + **消亡条款（见下）** |
| 升档×续谈运行态纠缠 | 中 | §2.4 明文"升档即冷启动" |

**回退开关（P6 重设计，替代 v0.2 的 config 一行开关）**：

- **载体**：代码常量（如 lib/index.js 顶部 `const CONTINUATION_ENABLED
  = false`）。理由：execute() 现只读 config.ministers，无透传通道；
  且 profile patch 是整段替换语义（verify.mjs P7 只盯 ministers 键），
  config 承载会被旧 profile 静默吃掉。
- **初值**：**false**。一次 G1 存在性探测不配翻转一个方案自认"高"风
  险的默认。
- **翻转规则**：仅由实证记录翻转——G1+G2+G5 全过且 n≥3 场续谈实跑无
  退化后，改代码常量为 true，并在 docs/ 留实证记录索引。
- **消亡条款**：双形态是受控实验态而非永久形态——**v0.3 发布前必须
  二择一**：要么实证充分、翻转默认（冷启动降为灾备路径），要么删除
  续谈半边回到单一形态。feature flag 不得无限期双活。

## 六、实施顺序（P8 修订：一天出成本裁决）

1. **D1（零代码探针场，advanced 档）**：开一场 advanced 议事作探针
   ——同议题同席位，1 席 R2 走 send_message 续谈、1 席走冷启动全新
   委派；先跑 ≤20 字最小探针定计费口径，再跑对照（约 20K 预算，远低于
   全席 54K）。
   **为什么不用 standard**：standard=4×1 轮且计划文本明文"不要使用续
   谈"（lib/index.js:379-380）——在 standard 上验续谈，验的是计划里
