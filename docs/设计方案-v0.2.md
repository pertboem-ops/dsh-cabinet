# dsh-cabinet v0.2 设计方案（续谈化）

> 基线：v0.1.1（2026-10-09 首场真跑 + 内阁审议吸收后）
> 主题：把阁员从"一次性并发 + 冷启动重建"升级为"存活席位 + 持续质询"——
> 方向性依据是 Deep Think 证明的"多分支 + 迭代精炼 > 单次推理"（见
> docs/设计方案.md §〇及会话内对照分析），但本方案不把该旁证当证据：
> 全部切换以 §三 的前置实证门槛为准。
> 状态：方案文本，不实建。

---

## 一、目标与非目标

**目标（按优先级）**：

1. R2 质询轮与点名追问改用 `send_message` 续谈存活席位，消灭"人格 +
   角色卡 + 己身 R1"的重复内嵌（首场实测 R2 简报约 ×1.8 参考轨的主因）。
2. 立场连续性从"文本重建"升级为"会话承载"——质询回应由写过 R1 的同一
   个存活子智能体产生，消除克隆体立场漂移。
3. 为纪律层补机器回读：归档审计器（events 对账 cost.calls）。

**非目标（明确不做）**：

- 不改变阁员隔离不变量（阁员之间仍不直接通信，父智能体仍是唯一集成点；
  续谈只发生在 主持人↔席位 这条边上）。
- 不动 R1 的并发派发形态、议定书 schema v2、角色包与钉扎表结构。
- 不引入 agent-team 实验包（团队任务板/成员互发与隔离不变量冲突，v0.1
  评估结论维持）。

## 二、核心变更：席位生命周期

### 2.1 现状（v0.1.1）

```
R1: spawn 席A(简报=人格+角色卡+议题+材料) → 立场书 → 席位死亡
R2: spawn 席A′(简报=人格+角色卡+席A立场书原文+对手原文+质询点) → 回应
```

立场连续性 = 内嵌原文；成本 = 每轮重付全量简报。

### 2.2 v0.2 目标态

```
R1: spawn 席A(continuable, 简报同 v0.1) → 立场书 → 席位存活（保留 id）
停等: 席位随父智能体回合边界挂起（dsh continuable 语义，待 G1 实证）
R2: send_message(席A, 消息=对手材料原文+质询点+输出格式要求) → 回应
```

- 省下的：人格文本、角色卡、该席自己的 R1 原文（约每场 R2 简报量的
  40–55%，按首场 34K 估约 8–11K token/场）。
- 不省的：对手 R1 原文（隔离不变量决定它只能经主持人传递，"全文优先、
  摘录兜底"规则不变）。
- 点名追问同理走 send_message，不再全新委派。

### 2.3 不变量改写（v0.1.1 原文 → v0.2）

> 旧：**不使用续谈**……停等边界之后一律全新委派。
> 新：**续谈优先、冷启动兜底**。席位自 spawn 起持续存活至合议；任何一次
> send_message 失败/超时/目标席位已终止，立即退回 v0.1 路径——全新委派 +
> 简报内嵌该席全部已有材料（人格+角色卡+R1 原文），计 reassigns。灾备表
> 增一行：`席位会话丢失/压缩失真 → 冷启动重派，disclosure 注明退化`。

### 2.4 诚实规则增补

续谈后主持人看不到席位的完整内部推理历史（只见报告），议定书
disclosure 增固定一句："本场立场连续性由各席会话承载，主持人可见面
= 各席报告文本"。归档的 round-N.jsonl 仍是权威记录——若某席 R2 与其
R1 出现无解释的立场翻转，主持人须在 divergence 记"新发现"而非默认其
已被说服。

### 2.5 预算公式影响

- 调用轨口径不变（spawn 与 send_message 都计委派次数；cap 公式
  `seats*rounds + seats + 1` 不动）。
- token 轨：标称值下调待首场续谈实测后修订 tiers.json（预估 standard
  19K→约 15–16K；先用 v0.1 数值跑，deviation 逐场记录，n≥3 场后改数）。

## 三、前置实证门槛（不过门槛不切换）

| # | 假设 | 验证方法 | 通过判据 | 失败则 |
|---|---|---|---|---|
| G1 | continuable 席位活过父智能体停等边界 | 开 standard 档一场，R1 停等后对一席 send_message | 席位响应且记得自己的 R1（抽查其引用 R1 细节） | v0.2 核心不切换，维持冷启动 |
| G2 | 存活席位的上下文压缩不丢 R1 关键内容 | G1 同场：要求该席逐字复述其 R1 "最坚持的一点" | 逐字一致 | 降级为"续谈+简报仍内嵌己身 R1 摘要"混合形态 |
| G3 | token-meter 暴露子智能体用量 | 查 dsh 计量面板的会话用量构成 | 能区分宿主/子智能体消耗 | token 轨维持"接口口径估算"措辞 |
| G4 | 宿主暴露派发拦截点（tools/pre-execute 可对 subagent 调用计数） | 读 dsh-tools 源码确认 guards 签名 + 写一个只计数不拦截的探针插件实跑 | 探针在真实议事中计数与 events 一致 | 预算硬执法继续靠自律 + 审计器 |

G1 是硬门槛；G2 失败有降级形态；G3/G4 不阻塞续谈切换。

## 四、同批进入 v0.2 的次席变更（首场审议 P4/P6/P9/P10 吸收）

1. **归档审计器**（约 20 行脚本）：读 `.cabinet/*/events.jsonl` 重建实际
   委派次数，对账 protocol.cost.calls；对不上即报。v0.2 起每场归档后
   必跑，结果写入 index.jsonl 新列 `audit`。
2. **人格改路径引用**：计划不再内嵌八席人格全文，改为给 ministers/ 绝对
   路径 + 读取指令；前提门槛：verify.mjs 增加"计划所载人格哈希 ==
   ministers 文件哈希"机检（防父智能体读到旧版无人对拍）。不满足则
   维持内嵌。
3. **events.jsonl 收窄为最小集**：seq/t/phase/actor/event 五字段 +
   派发/送达/预算三类必记事件（v1.1 的可选繁饰降级为建议）——审计器
   是其第一个真实消费者，格式随消费者定型。
4. **ROI 计数**：index.jsonl 每场增 `calls` 与 `gate_blocks`（闸拦截
   次数，如红队异源中止、预算触顶）两列，回应"年使用频率/闸防住过哪次
   事故"的 ROI 死穴。
5. **故障注入测试**：verify.mjs 增一组 smoke——构造钉扎全不可用、
   空 sessionModel 两类静默故障场景，断言计划文本仍含响亮中止路径。

## 五、风险与回退

| 风险 | 等级 | 缓解 |
|---|---|---|
| 续谈语义与文档不符（dsh rc 阶段行为漂移） | 高 | G1 硬门槛；版本闸 peer 已在 v0.1.1 就位 |
| 席位长期存活导致上下文膨胀、质量反降 | 中 | G2 抽查；连续两场 deviation 恶化即回退冷启动 |
| 双形态（续谈/冷启动）并存增加规程复杂度 | 中 | 计划文本单真源：buildInstruction 按 feature flag 出两版，verify 机检两版关键句 |
| 路径引用人格后父智能体漏读/读旧版 | 中 | §四.2 的哈希机检不过门槛则不换 |

回退总开关：cordis.patch.yml 的 config 增 `continuation: false`（默认
true 仅在 G1–G2 通过后打开），一行退回 v0.1.1 全冷启动行为。

## 六、实施顺序（供实建时遵循）

1. G1–G4 实证（不改代码，只跑探测；半天以内）。
2. 归档审计器 + events 最小集 + ROI 计数（消费实跑产物，先行）。
3. buildInstruction 增续谈版计划模板 + feature flag + 灾备新行。
4. 发布门补：双模板关键句机检、人格哈希机检（若 §四.2 达标）、
   故障注入用例。
5. 首场续谈实跑（standard 档）→ 对照 v0.1 首场的 deviation/质量；
   n≥3 场后修订 tiers.json 标称值。

## 七、验收标准

- G1–G4 各有明确实证记录（写入 docs/）。
- 续谈场次的议定书质量不劣于冷启动基线（对照评审判据：cites 齐全率、
  立场翻转有无解释、degraded 率）。
- standard 档 token 参考轨实测中位数下降 ≥25%，否则续谈化收益不成立，
  回退并归档结论。
