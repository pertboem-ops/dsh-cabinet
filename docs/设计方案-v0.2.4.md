# dsh-cabinet v0.2.4 设计方案（组阁确认停等点 + Lead 预答对照组 + 共识强度显式化）

> 基线：v0.2.2（已实建，verify 51 项 + smoke 54 项全绿）
> 本稿合并 v0.2.3（组阁确认停等点）与两个 Deep Think 借鉴机制为一版，
> 三机制同批实建。v0.2.3 独立文档废止，以本稿为准。
> 状态：方案文本，不实建。

## 〇、三机制总览与共用动机

| 机制 | 插入点 | 成本 | 解决什么 |
|---|---|---|---|
| **A. 组阁确认停等** | 组阁后、R1 派发前 | 零（停等在首次派发前，calls 恒 0） | 失配披露时序错位——看到时 token 已烧完（10-09 首场锋撞同源即活例） |
| **B. Lead 预答对照** | intake 后、组阁前 | 零（Lead 自回合不计调用轨） | 价值不可测——异见是否异源增量的代理指标（锋 dissent"价值测量被诚实搁置"） |
| **C. 共识强度显式化** | R1 速览格式 | 零（纯文本格式） | 共识面需用户自行反推 |

三机制共用一个设计红利：**全部落在零委派区间**（派发前或主持人回合），
预算公式、调用轨 cap、灾备路径一律不动。

## 一、机制 A：组阁确认停等点

### 1.1 流程插入点

```
intake → Lead 预答落档（机制 B）→ 第 0 步前置检查（组阁+三维检查+路由核对）
→ 第 0.5 步【组阁确认停等】→ 第 1 步 R1 派发 → 第 2 步速览停等（机制 C 改版）
```

第 0.5 步是**强制停等点**，与"R1 后必停"同级：未获用户显式确认不得派发
任何席位。

### 1.2 组阁确认卡

```
## 组阁确认（未派发任何席位，calls 0/N）

议题：… ｜ 档位：standard（4席×1轮）｜ 续谈模式：关

| 席位 | 阁员 | provider | model | 思考强度 | 钉扎=实际？ |
|------|------|----------|-------|---------|------------|
| 红队批判官 | 锋 | kimi-coding | k3 | high | 一致 |
| 架构官 | 远 | kimi-coding | k3 | high | 一致 |
| 工程官 | 谋 | zai-coding-cn | glm-5.3-flash | 继承默认 | 一致 |
| 成本官 | 众 | deepseek-account | deepseek-flash | max | 一致 |

三维检查：气质 4 异 / 立场 4 异 / 模型 3 家族；红队异源 ✓（vs 会话 glm-5.3）
失配披露：（无 / 逐席列出并注明已写入该席简报）
Lead 预答摘要：（机制 B 产出，100 字内——供你改定组阁时参照）

可回复：
- "组阁确认" / "开议" —— 按上表派发
- "锋换成 zai-coding-cn/glm-5.3 high" —— 改定某席（可多条）
- "免确认直接开" —— 跳过本停等点（仅本场）
- "散会" —— 终止
```

### 1.3 用户改定规程

1. 改定逐条落回组阁表后**重跑完整检查**（路由核对 + 三维不重合含红队
   异源失败关闭），任一不过 → 不出新卡，直接说明哪条不合规。
2. **红队铁律的用户覆盖通道**：改定致红队与会话同源的，响亮提示风险并
   要求二次确认；用户坚持则放行，disclosure 大写标注"红队同源系用户
   显式覆盖铁律"——铁律默认值由机制给，最终裁量权在用户，覆盖必留痕。
3. 改定后**重新输出确认卡再等一次确认**——改定不直接触发派发。
4. events 记录：组阁呈现（setup）、用户改定内容（steering）、确认动作
   （steering）；用户否决掉的红队违规改定计入 index 的 gate_blocks。

### 1.4 免确认通道边界

"免确认直接开"仅当场有效、须用户显式说出，不设 config 级默认——否则
机制退化为可被遗忘的默认值。快速通道给熟手，默认值保护所有人。

## 二、机制 B：Lead 预答对照

### 2.1 流程

- **写入点**：intake 之后、组阁之前（第 0 步第 0 条）。Lead 对议题写
  独立预答：≤400 字，固定三段（我的结论 / 我最支持的一条论据 / 我认为
  最大的风险），落档 `.cabinet/<场>/preanswer.md`。
- **隔离铁律**：预答**只入档与确认卡摘要，绝不进任何席位简报**——进
  简报即污染独立性，该场预答作废（protocol 记 `beyond_preanswer: null`
  并注明原因）。
- **对照点**：合议时逐条对照议定书 decisions 与已解决/部分弥合的分歧
  裁决，"实质内容未出现在预答中"的计为超预答结论。

### 2.2 防自评自裁

对照判定者是 Lead 自己（它写了预答也写了议定书）——因此**不许只报
总数 N**：议定书必须逐条列出"结论 ↔ 预答覆盖情况"对照表，N 只是索引，
对照表才是证据，用户可抽查。

### 2.3 判读规则（防误用，写入技能文本）

- N 是趋势指标不是评分：单场 N=0 不说明任何问题；连续 ≥5 场 N≈0 才
  构成"装置在生产 Lead 自己就会说的答案"的初步证据，举证责任此时转移
  到开阁方。
- **N 趋零不是内阁无价值的充分条件**（也可能是 Lead 强/议题浅）——必要
  条件方向的代理指标，不是假设检验。措辞禁用"对照组实验"，称"预答基线
  对照"（n=1 单臂，无统计功效）。
- 预答缺失（Lead 跳写）的场次：`beyond_preanswer: null`，禁止回填。

## 三、机制 C：共识强度显式化

R1 速览格式改为对举两栏：

```
**共识面**（已稳，无需你裁）
- [全场一致] …（锋/远/谋/众）
- [多数] …（远/谋/众；锋反对见 D2）

**分歧面**（需要你裁）
- D1 …（锋 vs 远）
```

**两条纪律**：

1. 强度标签**必须枚举支持席位名单**——阁员被角色卡刻意推向对立立场，
   "被推开仍收敛"强于同源采样收敛，但只有列出谁支持谁反对，用户才能
   看出收敛是否来自同质席抱团。强度三级（全场一致/多数/分裂）封顶，
   4 席样本上更细的刻度是伪精确。
2. 共识面只供阅读，**不构成跳轮依据**——跳轮仍只看提前收敛边界
   （实质分歧计数），"R1 后必停"不变。

## 四、与既有机制的交互

| 既有机制 | 交互 |
|---|---|
| R1 后必停 | 变为两处必停：组阁确认（0 成本，R1 前）、速览停等（R1 后） |
| 红队铁律三修（P3） | 不变；新增"用户显式覆盖"留痕通道（此前铁律无出口） |
| 续谈形态（CONTINUATION_ENABLED） | 正交——确认卡照常标注续谈模式，两形态共用本停等点 |
| 预算双轨 | 零影响——三机制均不消耗委派额度 |
| 升档 | 升档重调 start 后组阁变化 → **新场重新过组阁确认**（与"升档即冷启动"同源：新计划不继承旧场运行态）；预答不重写（议题未变） |
| 三维检查 | 从"组阁后必做"变为"确认卡的前置条件"——不过则不出卡、直接报错 |
| 评分卡 | 不变（仍决定开不开阁、开哪档） |

## 五、改动面清单（实建时遵循）

1. **lib/index.js** `buildInstruction`：
   - 第 0 步新增第 0 条"Lead 预答"（三段式、≤400 字、落档 preanswer.md、
     隔离铁律）；
   - 第 0 步末尾插"第 0.5 步——组阁确认停等"段（确认卡模板 + 改定规程 +
     铁律覆盖通道 + 免确认短语 + 预答摘要行）；
   - 第 2 步速览格式改"共识面/分歧面"对举模板（强度三级 + 席位枚举）；
   - 合议步新增"预答对照"子步骤（逐条对照表 + N 计数）；
   - 议定书 schema 块增 `beyond_preanswer` 字段；
   - 归档段增 preanswer.md，index.jsonl 增 `beyond_preanswer` 列。
2. **skills/cabinet.md**：核心纪律增"组阁后必停"（确认卡→等用户→改定
   重检→再确认→才派发）与"预答先于一切席位产出、只入档不入简报"；
   "R1 后必停"措辞改为两处必停；速览格式段与议定书字段段同步。
3. **schemas/protocol-v2.json**：fields 增 `beyond_preanswer`

5. **smoke.mjs**：顺序断言（预答步骤 < 组阁确认 < R1 派发）；格式断言。

## 六、故障与边界

| 情形 | 处置 |
|---|---|
| 用户不回复组阁确认 | 停等即终态，不烧 token；会话自然搁置 |
| 改定路由不存在 | 路由核对 FAIL，说明并留在确认环节 |
| 改定致三维检查不过 | 说明哪维、给修复建议，留在确认环节 |
| 改定致红队同源 | §1.3-2：响亮提示→二次确认→放行留痕 |
| 免确认后中途想改模型 | 走轮间介入（点名/散会），或散会改 config 重开 |
| Lead 跳写预答 | beyond_preanswer: null + 注明，不阻断议事 |
| 共识面全满（零分歧） | 仍按提前收敛边界处理："首轮即收敛"须注明才可合议 |

## 七、验收

- 渲染目检：顺序 = 预答 < 组阁确认卡 < R1 派发；速览模板两栏且强度带
  席位枚举；议定书 schema 含 beyond_preanswer；双形态（continuation
  开/关）各渲一次。
- 首场实跑核对：确认卡呈现→用户改定一席→重检→再确认→派发；
  preanswer.md 落档；议定书含逐条对照表；index 行有 beyond_preanswer 列。
- 数据积累 ≥5 场后回读 index.jsonl，评估预答指标的判读稳定性，再决定
  是否升级为正式裁决依据（B 批裁决的数据分母）。
