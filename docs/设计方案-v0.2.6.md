# dsh-cabinet v0.2.6 设计变更（组阁披露卡恢复停等·提问式确认）

> 基线：v0.2.5（已实建）→ 本版（已实建）。
> 性质：**用户显式裁决**，推翻 v0.2.5 审议场 P2（"披露卡照出即继续、
> 不停等"）。审议理由全文保留于 docs/设计方案-v0.2.5.md，本稿不删除、
> 不粉饰。

## 变更内容（唯一项）

第 0.5 步从"披露卡照出即继续"改为"披露卡 + `ask_user_question` 提问 +
停等"：

- 卡组阁披露内容不变（席位/阁员/provider/model/思考强度/钉扎对照/三维
  检查/失配披露/守护半径）。
- 卡后调用 `ask_user_question`：确认开议 / 改定席位模型 / 散会。
  **未获显式"确认开议"不得派发任何席位**（calls 恒 0 于确认前）。
- 改定规程恢复 v0.2.3 形态：落回组阁表 → 重跑路由核对与三维检查 →
  出新卡 → 再次提问；改定不直接触发派发。
- `card_reactions` 列口径改为 确认/改定/散会（旧口径 中断/提及/无 随
  不停等版废止；旧档不回填）。

## 被推翻裁定的留存与回应

| v0.2.5 裁定理由 | 本版回应 |
|---|---|
| 卡不产新证据，停等是仪式重放（远 P2） | 成立但不决定性——用户要的不是新证据闸门，而是**每场必见的否决点**；裁决权在用户 |
| 沉默用户永久锁死（锋 R2） | 用户知悉并接受；`ask_user_question` 的结构化表单使锁死状态明确可恢复（重新作答即继续），且中断通道仍在 |
| 硬闸已代码层拦截，卡只管软失配（众） | 保留为守护半径条款，不变 |

日落条款调整：A 机制的"连续 3 场 card_reactions=0 → 降级"在停等版下
不再适用（提问强制产生答复）；如未来用户想回退不停等版，机制日落动作
= 从 MECHANISMS 删 "A-card" 键。
