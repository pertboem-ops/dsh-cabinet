## 一、机制 A′：组阁披露卡（默认继续）

### 1.1 流程插入点

```
intake → 第 0 步前置检查（组阁+三维检查+路由核对，失败关闭不动）
→ 第 0.5 步【组阁披露卡】照出 → 直接进第 1 步 R1 派发 → 第 2 步速览停等（机制 C 改版）
```

**不设强制停等**（P2，远裁定：卡的全部内容第 0 步已算完，卡不产新证据，
只是重放——与"R1 后必停"保护新证据的先例不同构）。卡的文案按**"供
阅读"**写、不按"待批准"写：保护责任不得假定给一个不在场的用户（锋
R2 重构原则）。沉默=议程正常推进；中断/散会通道在派发前后任何时刻
有效——改定循环（改定→重检→再确认）整体消失，不满意=直接说，走既有
轮间介入通道。

### 1.2 披露卡模板

```
## 组阁披露（供阅读，议程将继续——如需调整请直接说明）

议题：… ｜ 档位：standard（4席×1轮）｜ 续谈模式：关

| 席位 | 阁员 | provider | model | 思考强度 | 钉扎=实际？ |
|------|------|----------|-------|---------|------------|
| …（逐席六列，同第 0 步已算结果）|

三维检查：气质 4 异 / 立场 4 异 / 模型 3 家族；红队异源 ✓（vs 会话 …）
失配披露：（无 / 逐席列出并注明已写入该席简报）
守护半径：本卡只披露软失配；硬闸（红队异源/三维失败关闭）已在派发前
由代码层拦截，不在本卡重复裁决。
```

（v0.2.4 确认卡的"可回复选项"块与"免确认直接开"咒语**删除**——不等
版下无意义。）

### 1.3 守护半径条款（P2，众）

- 卡只保**软失配披露**（钉扎配置病一类的可见性）；硬闸已拦的不重拦。
- 若软失配源于 config 钉扎病，正解是改 cordis.patch.yml（修一次永久
  消除），卡只承担"让用户看见"的职责。

### 1.4 误拦恢复通道（P3，远）

- **检测与恢复分权**：检测归代码层——checkSeatDimensions 失败关闭
  （含红队异源不可判定即中止）语义不变；本通道**只管误拦恢复**：当
  用户确信失败关闭系误报（如宿主模型自报信息错误），可显式说
  "误拦恢复：按 X 继续"。
- 放行时：disclosure 大写标注"三维失败/红队同源系用户显式**误拦恢复**"；
  **gate_overrides 独立列**计数（与 gate_blocks 分列：拦截止 gate_blocks、
  放行入 gate_overrides——越稀有的越不能混账）。
- 文档禁用"风险裁量/最终裁量权在用户"表述（防责任转移叙事）；注记：
  提示词闸门三年必腐，该列即腐化日志（锋）。

### 1.5 首场对照观察（一次性，可选）

首场实跑可选用停等版做一次对照（记录用户是否反应、反应时延），此后
固定不等版——为 A′ 的日落判定攒第一颗数据。

## 二、机制 B：移除（占位与重启前置）（P4）

- **不建**：preanswer.md、卡上预答摘要行（v0.2.4 模板中的该行随 B 移除
  而删——A 卡与 B 产物的耦合就此解耦，远 R1-1 随之消解）、合议对照表、
  N 计数、判读规则段。
- **保留占位**：schemas/protocol-v2.json 增 `beyond_preanswer`
  （{count: null, items: []}，since "2.4-dsh"），index.jsonl 增
  `beyond_preanswer` 列；旧档/无 B 场次恒 null，**禁止回填**。
- **方法依据**（审席裁决入档）：预答测量链自指环（立论/判定/报告）三
  节一节不断；§2.3"降格趋势指标"是改标签非给尺子定标，自我防护免疫
  失败；"≥5 场攒基线"不消解方法指控——缓期≠治愈。
- **重启前置**（缺一不可）：① 指纹机检初判脚本（预答落档提取关键词
  集，初判交脚本、Lead 只复核——断自指"判定"节；锚定节与措辞敏感节
  风险原样存活，锋注）；② 议题确需价值测量；③ 判读规则重新过方法
  审查。重启论证责任在提案方。
- 锋的保留入档：锚定可能反向起纪律作用（未证）——重启时列为检验项。

## 三、机制 C：共识强度显式化（照建，P6）

R1 速览改两栏对举：**共识面**（[全场一致]…（席位枚举）/[多数]…（席位
枚举；反对者标见 D#））与**分歧面**（D1 …（甲 vs 乙））。

纪律三条：① 强度标签必须枚举支持席位名单（看出收敛是否来自同质席
抱团）；② 三级封顶（全场一致/多数/分裂），4 席样本上更细是伪精确；
③ 共识面只供阅读，**不构成跳轮依据**——跳轮仍只看实质分歧计数，
"R1 后必停"不变。

**日落条件**（P8）：连续 3 场用户追问均不涉及两栏 → 降为一行摘要
（判据写死，防维护税）。

## 四、与既有机制的交互

| 既有机制 | 交互 |
|---|---|
| R1 后必停 | 唯一强制停等不变（信息闸门先例）；组阁披露卡不再停等 |
| 红队铁律（P3 三修） | 检测语义不动（代码层失败关闭）；新增误拦恢复通道+gate_overrides 列 |
| 续谈形态（CONTINUATION_ENABLED） | 正交——卡照常标注续谈模式；两形态共用披露卡 |
| 预算双轨 | **零委派额度成本**（宿主回合文本与用户交互时间未计——P5 诚实标注） |
| 升档 | 升档重调 start 自然出新卡（披露性质，无确认/粘性问题——不等版下 v0.2.4 的"免确认粘性"难题消解）；"升档即冷启动"不变 |
| 三维检查 | 仍为卡的前置条件——不过则不出卡、直接报错（失败关闭） |
| mustCover | 增项（组阁披露卡呈现）按 schemaVersion 分版本生效（P9，防旧档回放误判） |

## 六、故障与边界

| 情形 | 处置 |
|---|---|
| 用户看完卡想调整 | 直接说（中断/改某席/散会）——轮间介入通道，派发前后均有效 |
| 软失配披露出现 | 用户自行权衡：改 config（正解，永久消除）或当场忽略 |
| 失败关闭误拦 | §1.4 误拦恢复通道：显式指令+大写标注+gate_overrides 计数 |
| 中断演练失败（宿主派发惯性压不住） | 首场实跑记录——远/谋镜像疑虑在案，A′ 依赖此验证 |
| 旧档回放 | mustCover 分版本生效；beyond_preanswer 恒 null 禁回填 |
| 共识面全满 | 仍按提前收敛边界："首轮即收敛"须注明才可合议 |

## 七、实施顺序（谋修正版排程）

- **D0**：render-context 对象提参+双值渲染框架（半天内）；
- **D1**：机制 C 两栏速览（半天）；
- **D2**：B 的 schema 占位+index 三列+审计器对齐（半小时）；
- **D3**：机制 A′ 披露卡（守护半径+误拦恢复文案，一天）；
- **D4**：cabinet.md 双侧同步+verify 短锚句机检+全门跑绿；
- **D5**：首场实跑（§八验收），含中断演练与可选停等对照。

## 八、验收（P9）

- 渲染目检：披露卡在 R1 派发前且**无任何等待确认语句**；两栏速览带席位
  枚举；schema 含 beyond_preanswer 占位；render-context 按
  continuation 开/关 × 已实建机制集各渲一次。
- 首场实跑三步核对：**卡照出 → 默认继续发生（R1 确实派发）→ 中断演
  练有效**（演练=卡后立刻说"停，改某席"，验证既有通道接得住）；可选
  一次性停等对照（§1.5）。
- index 行含 beyond_preanswer（null）/gate_overrides（0）/card_reactions
  三列；gate_blocks 与 gate_overrides 分列记账。
- 归档后跑 `node scripts/audit.mjs`，结论写入 index.audit。

## 九、日落条款汇总（P8，全部可机检）

| 机制 | 条件（数据源） | 动作 |
|---|---|---|
| A′ 披露卡 | 连续 3 场 card_reactions=0（index） | 卡降为 index 行，不再渲染正文卡 |
| A′ 披露卡 | 任一场中断命中 | 保留（并回填"中断演练"验证记录） |

| B（若重启） | 5 场 N 中位数=0 且覆盖率方差≈0（protocol.beyond_preanswer） | 判失效下线 |
